# RETD Production Readiness — Defect Register

Live register for defects found during Phase-2 validation. Scheme per the master prompt:
`id, gate, severity, repro, evidence`; P0/P1 fixed with a regression test in-session,
P2/P3 fixed when cheap, otherwise logged for the release backlog. BLOCKED-EXTERNAL items
carry exact hand-off notes.

Severity: **P0** = exploitable / negligent (data loss, breach, unrecoverable);
**P1** = significant security or integrity defect; **P2** = hardening gap;
**P3** = operational / process note.

## Backlog (closed since the last sweep)

- P2 (closed): Offline field writes commit the entity and the sync-ledger row in two separate
  DB transactions; a crash in the tiny window between them could lose idempotency for that one
  write. **Fixed:** the entity create + audit + `SyncService::record` are now wrapped in a
  single `DB::transaction` in `DiscoveryController::store`, `EvidenceController::store`,
  `GpsController::certify` (both decision branches) and `EnforcementController`
  (`assignmentAction`, `recordVisit`, field-discovery capture); `submitReceipt` was already
  atomic. Regression: `tests/Feature/AtomicWriteGuardsTest.php` simulates a ledger outage and
  asserts the entity (photo / discovery / GPS history) and `sync_transactions` both stay at zero.
- P3 (closed): `Task::transitionTo` read the current status in memory and then `save()`ed; two
  concurrent transitions from the same state could write duplicate `task_histories` rows.
  **Fixed:** commit is now an optimistic status-guarded update
  (`static::whereKey($id)->where('status', $from)->update(...)`); a stale concurrent
  transition throws `InvalidArgumentException` with "changed concurrently". Same-state
  idempotent no-ops unchanged. Regression: `test_concurrent_transition_is_rejected_by_optimistic_guard`.
